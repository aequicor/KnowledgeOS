# Правила написания гайдлайнов

## Структура frontmatter

```yaml
---
genre: guideline
title: Краткое название
topic: ключевая-тема
library: имя-библиотеки  # опционально
triggers:
  - "фраза-триггер"
  - "другая-фраза"
related:
  - [[связанный-документ]]
confidence: high  # low | medium | high
source: agent     # agent | human
updated: 2026-04
---
```

## Правила

1. **Один гайдлайн — одна тема.** Не смешивай разные правила в одном документе.
2. **Конкретика, не абстракция.** Пиши "используй `try/catch` с логированием ошибки" вместо "обрабатывай ошибки правильно".
3. **Триггеры обязательны.** Список `triggers` помогает агенту найти гайдлайн. Указывай ключевые фразы, которые агент может использовать в поиске.
4. **Связанные документы через `[[wikilinks]]`.** Связывай гайдлайн с концептами и другими гайдлайнами.
5. **Обновляй дату.** При каждом изменении ставь текущий месяц в `updated`.
6. **Confidence отражает проверенность.** `low` — новое правило, `medium` — использовалось пару раз, `high` — проверено многократно.

## Антипаттерны

- Гайдлайн без триггеров — агент не найдёт его
- Гайдлайн без wikilinks — потерян контекст
- Слишком общие правила ("пиши хороший код") — бесполезны
